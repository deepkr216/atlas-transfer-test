# F15-ws-exec-sql-no-period - an EXEC SQL in WORKING-STORAGE with no period after its END-EXEC erases every procedure-division fact while the member reads ok

The DECLARE CURSOR's END-EXEC lacks its period (whether a compile rejects that depends on the step that read the block - a separate DB2 precompiler turns it into comment lines first - LESSONS 212). The toolkit is not a compiler and need not accept it - but it says nothing: no paragraphs, no PERFORM, no OPEN, and `parse: ok`. A member with a data division and no paragraphs is a shape worth one line in the notes.

Fixed by ROADMAP re-parse item 26 (LESSONS 211): the reader closes the statement at the END-EXEC when no period follows before the PROCEDURE DIVISION, so R15NOP keeps 0000-MAIN and 1000-OPEN and the PERFORM between them; the member is `partial` with the note 'EXEC SQL at line 6 has no period after its END-EXEC; what follows was read as if it had one'. The synthetic estate's POLUPD05 findings (F16, F17, F21-F24 of the report) came from another shape with the same effect - the 8-digit stub POLSTUBC expanded as code ran the data entry on into the division header - and ROADMAP re-parse item 23 fixed those. A data entry that runs on into the header for another reason (a COPY NOT FOUND inside a VALUE clause) is ROADMAP re-parse item 25, still open.
